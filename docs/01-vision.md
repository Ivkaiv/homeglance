# 01 · Видение и философия

## Зачем нужен Glance

Home Assistant — мощная система, но её стандартный интерфейс **Lovelace** делался разработчиками для разработчиков. Чтобы что-то настроить, нужно:
- Лезть в YAML или Visual Editor (который всё равно неуютный)
- Знать что такое `entity_id`, `device_class`, `card type`
- Терпеть ограниченное число встроенных тем
- Самому собирать комнатную «сцену» из десятка карточек
- Жить с топорным дизайном — никаких эффектов «жидкого стекла», свечения, плавности iOS

Большинству домашних пользователей это не подходит. Они хотят:
- Открыть приложение на айфоне → видеть только то, что им важно
- Перетаскивать виджеты пальцем как иконки на home screen
- Настраивать без YAML, в три тапа
- Современный визуал — стекло, свечение, тёмная тема, мягкие анимации

Lovelace это не предлагает. Glance — да.

## Кто наш пользователь

**Аватар:** обычный человек, который купил умный дом и хочет им управлять с телефона. Не разработчик, не системный администратор. Возможно, у него Apple-окружение и привычки iOS. Он ценит красоту и простоту, не любит конфиги и команды.

Сценарии:
- Утром сидит за кофе, смотрит на панель — погода, температура в комнатах, что включено
- Уходя из дома, тапает виджет «Все лампы» → выключить
- Видит освещение во дворе → тапает → включает
- На стене висит планшет — он же показывает погоду, температуру, медиа
- Жена / дети / гости имеют свои дашборды — каждый видит то, что ему важно

## Чего мы НЕ делаем (анти-цели)

- **Не пытаемся быть Lovelace** — у Lovelace другая ниша (мощный, гибкий, для админов)
- **Не делаем YAML** — не должно быть никакого «отредактируй конфиг»
- **Не требуем установки на стороне HA** — кроме самой панели через HACS, никаких custom integrations, helpers, automations
- **Не делаем универсальный конструктор для всего** — фокус на повседневном смарт-доме (свет/климат/сенсоры/комнаты/медиа), а не редкие use-cases

## Принципы дизайна

1. **iOS-first эстетика** — стекло, свечение, прозрачность, плавность, мягкие тени
2. **Pixel-perfect** — каждый отступ, каждый шрифт под контролем
3. **Mobile-first** — десктоп — это «mobile, растянутый по ширине», не отдельный дизайн
4. **Адаптивные виджеты** — каждый виджет умеет ужаться до иконки и развернуться до подробной карточки
5. **Тап → действие** — никаких трёх-шаговых меню для самого частого действия
6. **Редактирование = режим, а не отдельная страница** — кнопка «Редактировать» включает «дрожание», как на iPhone

## Принципы технические

1. **Никаких HA-изменений** — только REST/WebSocket API
2. **Self-hosted, off-line capable** — работает в локальной сети без интернета
3. **PWA-first** — установка на home screen, push-уведомления (потом)
4. **Type-safe** — TypeScript, без `any` где можно
5. **Расширяемо через виджет-API** — виджеты как плагины, легко добавлять новые
6. **MIT license** — open source, контрибьюторам легко присоединиться

## Сравнение с альтернативами

| Аспект | Lovelace | Glance | Home Assistant Companion App |
|---|---|---|---|
| Конфиг | YAML / Visual Editor | Drag-and-drop | Только настройки |
| Дизайн | Material 2018 | iOS-вдохновлённый | Платформенный (iOS/Android native) |
| Mobile UX | Адаптивный, но десктоп-first | Mobile-first | Native |
| Доступ извне | HA Cloud / port-forward | Сам HA + URL | HA Cloud / port-forward |
| Multi-user | Через HA users | Локальные профили + опциональная HA OAuth | HA users |
| Установка | Встроено | HACS add-on | App Store / Play |
| YAML | Да | **Нет** | Нет |

Главное отличие от Lovelace — **mobile-first + современный дизайн + zero-config**. Главное отличие от Companion App — **контролируется пользователем** (можно ставить на стенной планшет, кастомизировать, форкать).
