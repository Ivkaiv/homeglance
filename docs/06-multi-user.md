# 06 · Многопользовательский режим

## Концепция

Несколько домочадцев пользуются панелью на разных устройствах (или одном). У каждого свой набор страниц, своя раскладка, свои предпочтения. Выбор пользователя при первом запуске — потом запоминается.

## Архитектура профилей

```
┌────────────────────────────────────────────────┐
│  Glance Instance (на устройстве)               │
│                                                │
│  ┌──────────────────────────────────────┐     │
│  │  Активный профиль: 👤 Юрик           │     │
│  │  ↑ переключатель в углу              │     │
│  └──────────────────────────────────────┘     │
│                                                │
│  ┌──────────────────────────────────────┐     │
│  │  Список профилей:                     │     │
│  │   👤 Юрик     [active]                │     │
│  │   👤 Аня                              │     │
│  │   👤 Гость                            │     │
│  │   + Добавить профиль                  │     │
│  └──────────────────────────────────────┘     │
└────────────────────────────────────────────────┘
```

Каждый профиль:
- Имя
- Аватар (эмодзи или фото)
- PIN (опционально)
- Свои страницы и раскладки
- Свои настройки (темы, цвет акцента)

## Хранение

```ts
interface Profile {
  id: string;            // uuid
  name: string;
  avatar?: string;       // emoji или dataURL фотки
  pin?: string;          // hash, опционально
  pages: Page[];
  settings: UserSettings;
  createdAt: number;
  updatedAt: number;
}

interface ProfilesState {
  profiles: Profile[];
  activeId: string;
}
```

В localStorage:
- `glance:profiles` — массив профилей
- `glance:active-profile` — id активного

## Сценарии

### Первый запуск (на новом устройстве)
1. Видит экран "Привет, добро пожаловать в Glance"
2. Ввод имени → создаётся профиль
3. Демо-страница с виджетами на основе доступных HA-сущностей
4. Дальше — режим edit для кастомизации

### Переключение профиля
- Тап на аватар в углу → дроп-down со списком
- Выбор → перезагрузка дашборда

### Защита PIN
- Профиль может быть с PIN (4 цифры)
- При выборе такого профиля — экран ввода PIN
- Полезно если на стенном планшете висит «гостевой» профиль, но «полный» — под защитой

### Гостевой режим
- Специальный профиль с ограниченными правами (read-only? выключенные edit?)
- Появляется если включён в настройках

## Sync между устройствами

В **MVP** — sync нет. Профиль живёт на устройстве. Чтобы перенести — нужно экспортировать.

В **v1** — добавляем:
- **Export / Import** — JSON-файл с профилем (можно отправить себе в TG)
- **QR-код** — на старом устройстве жмёшь "поделиться", показывает QR; новое устройство сканирует → получает профиль

В **v2** — настоящий sync:
- Через бэкенд Glance (если он развёрнут на HA-инстансе вместе с панелью)
- Через HA `frontend_storage` API (родной storage)
- Через любой sync-провайдер (Dropbox, ICloud — для запасливых)

## Связка с HA users (опционально)

В **v2** можно добавить интеграцию с HA OAuth. Тогда:
- Профиль Glance автоматически связывается с HA user
- Долго-живущий токен генерируется автоматически
- При выходе пользователя из HA — токен инвалидируется

Это даёт «настоящий» multi-user, где разные пользователи имеют разные права в HA.

## Ролевая модель

В **MVP** — все профили равны (могут всё).

В **v1** добавляем роли:
- **Owner** — может всё, включая управление профилями
- **User** — может управлять своими страницами, не может создавать новые профили
- **Viewer** — read-only, ничего не редактирует, не нажимает кнопки (например, для младших детей)

## Защита и приватность

- PIN хранится как **bcrypt-хэш** в localStorage (не plain)
- При утере PIN — единственный способ — сбросить профиль (потеря раскладки)
- Можно включить «авто-выход» через N минут бездействия → возврат на экран выбора профиля
