Формат основан на [Keep a Changelog](https://keepachangelog.com/), проект следует

## [0.1.0-alpha.63] — 2026-05-18

### Fixed
- **При шаге температуры < 1 нажатие +/− визуально ничего не меняло.**
  Климат-виджеты (RoomHub, Climate, ClimateSheet) во всех местах рендерили
  target через `Math.round(target)` — значение менялось и улетало в HA, но
  на экране всегда показывалось округлённое до целого: пользователь нажимал
  «+» при шаге 0.1, реально получал 23.1°, но видел те же «23°» и думал,
  что регулировка не работает. Добавлена утилка `formatTemp(value, step)`
  — выбирает точность отображения по шагу (0 знаков при step≥1, 1 знак при
  0.1≤step<1, 2 знака при ещё меньшем).
- **Float-хвосты при многократном +/−.** `target + 0.1` много раз давало
  значения типа 23.30000000000001. Добавлена `applyStep` — округляет
  результат до точности шага перед отправкой в HA, в логах больше нет
  «грязных» хвостов.

## [0.1.0-alpha.62] — 2026-05-17

### Added
- **Свой шаг регулировки для каждой climate-сущности внутри RoomHubWidget.**
  Раньше общий `climateStep` применялся ко всем градусникам в комнате — но
  у котла удобный шаг 0.1, у конвектора 0.5, у кондиционера 1. Теперь в
  настройках виджета есть новый блок «Свой шаг для каждой сущности»:
  напротив каждой выбранной climate-entity — отдельное поле для шага.
  Если поле пустое, используется общий шаг как fallback.
- **Новый тип параметра `entity-numbers`** — связка с multi-entity-полем
  через `linkedKey`. Для каждой выбранной сущности показывает строку
  «имя + число». Универсальный механизм, пригодится и для других виджетов,
  где нужны параметры на сущность (например, индивидуальные пороги).

## [0.1.0-alpha.60] — 2026-05-17

### Fixed
- **Виджеты лампочек и переключателей теряли подпись на узких клетках iPhone.**
  `EntityToggleShell` использовал CSS container queries с порогом 140px:
  при ширине ~96px (мобильная сетка 9 cols × 32px) был только значок без
  названия — пользователь не понимал, какой именно свет он сейчас включит.
  Переписан с трёхуровневым layout: `<70px` только иконка, `≥70px` иконка
  + подпись маленьким шрифтом снизу, `≥140px` полный layout с заголовком
  сверху и статусом справа.
- **Убран «странный» полупрозрачный кружок-индикатор** рядом с иконкой
  в среднем размере EntityToggleShell. В выключенном состоянии он смотрелся
  как графический мусор; статус «вкл/выкл» теперь однозначно читается по
  самому glow карточки и цветной заливке иконки.
- **Виджет «Несколько сенсоров» в настройках не находил сенсоры.** Поле
  `domain` в `paramSchema` поддерживало значение со списком через запятую
  (`'sensor.,binary_sensor.'`), но фильтр `startsWith(domain)` никогда не
  давал совпадений. Добавлена утилка `matchDomain`, корректно разбивающая
  строку и сопоставляющая любой из префиксов. Фикс одновременно
  распространился и на `EntityPicker`, и на обычный `MultiEntityPicker` —
  все три места поиска теперь поддерживают multi-domain.
- **Шаг регулировки температуры был ограничен целыми числами.** Number-input
  в ConfigSheet рендерился без атрибута `step`, поэтому браузер по умолчанию
  использовал `step=1` и молча отбрасывал дробные значения — пользователь
  не мог поставить шаг 0.1 или 0.5 для котла / тёплого пола. У number-полей
  теперь `step='any'` по умолчанию (или из meta), `inputMode='decimal'`,
  поддерживаются `min`/`max`. Дефолт шага для climate-виджетов снижен с 1
  до 0.5, с возможностью ввести любое значение от 0.1 до 5.
- **Заголовок дашборда на iPhone заходил под status bar при скролле.**
  `header` с `sticky top-0` клеился к самому верху viewport, минуя
  `padding-top: env(safe-area-inset-top)` родителя (sticky-элемент не
  наследует safe-area-инсет контейнера). Перевешен на
  `top: env(safe-area-inset-top)` — и в покое, и при скролле шапка стоит
  ровно под notch / Dynamic Island.
- **iOS Safari автоматически зумил страницу при фокусе на поиске сенсоров.**
  Все text-input в ConfigSheet имели `text-sm` (14px), а iOS Safari
  принудительно зумит при font-size < 16px. Добавлено глобальное правило
  для touch-устройств (`@media (pointer: coarse)`) — все input/textarea/select
  получают минимум 16px шрифта. Визуально на мобиле почти не отличается
  от 14px, но Safari больше не дёргает зум при открытии клавиатуры.

## [0.1.0-alpha.58] — 2026-05-17

### Fixed
- **PIN-защита единственного профиля обходилась автологином.** В `ProfilesProvider`
  при наличии ровно одного профиля он автоматически активировался без проверки
  PIN — любой, кто открывал URL Glance с нового устройства, попадал прямо внутрь
  и видел все данные владельца. Теперь авто-вход срабатывает только для профилей
  **без** установленного PIN. Если PIN установлен (даже на единственном профиле),
  обязателен `ProfilePicker → PinPrompt` перед попаданием в дашборд.
- **PIN, установленный в HTTP-контексте, нельзя было ввести с HTTPS-устройства.**
  `hashPin` в insecure context (без `crypto.subtle`) падал на slabый
  `simple:`-fallback, но `verifyPin` всегда пересчитывал через sha256 — хэши
  не совпадали, любой PIN считался «неверным». Теперь `verifyPin` смотрит на
  префикс хэша (`sha256:` / `simple:`) и считает тем же алгоритмом, которым
  хэш был создан.

### Notes
- Если ваш сохранённый `pinHash` начинается с `simple:` — рекомендуется зайти
  в настройки профиля и переустановить PIN под HTTPS. Это пересохранит хэш
  в sha256-форме. `simple:` — фактически открытый текст для 4-значных PIN.

## [0.1.0-alpha.57] — 2026-05-16

### Added
- **Готовая страница «Сахар»** — мониторинг CGM из коробки. В редакторе страниц
  («Шестерёнка → Страницы») появилась секция «Готовые страницы» с кнопкой
  «🩸 Сахар — мониторинг CGM», которая разворачивает раскладку из четырёх
  виджетов: крупная карточка глюкозы, график динамики, статистика за 24 часа
  и за 7 дней.
- **Новая категория виджетов `health` 🩸 Здоровье.** Доступна через «+ Виджет»
  для добавления любого из новых виджетов в любую другую страницу.
- **Виджет `glucose` («Глюкоза»).** Большая карточка текущей глюкозы CGM:
  значение, юникод-стрелка тренда Nightscout (↑↑/↑/↗/→/↘/↓/↓↓), дельта,
  время с последнего замера, цвет фона по зоне (норма/выше нормы/высоко/
  опасно низко-высоко). Индикатор «сенсор молчит» при отсутствии данных
  более 15 минут. Тап открывает график за 6 часов.
- **Виджет `glucose_chart` («График глюкозы»).** SVG-чарт с подсветкой
  целевой зоны 3.9–7.8 ммоль/л, пунктирными линиями порогов low/high,
  цветными точками по зонам, переключателем 3/6/12/24 ч (использует
  `input_select.glucose_range` если есть, иначе работает локально),
  crosshair-указателем при тапе для просмотра конкретного значения.
- **Виджет `glucose_stats` («Статистика глюкозы»).** TIR (Time-In-Range)
  с прогресс-баром цвета по достижению цели 70%, среднее, GMI/HbA1c
  (только в режиме «За 7 дней» — за 24 ч он бессмысленен), % времени
  выше и ниже нормы. Каждый показатель кликабелен — открывает график
  истории.

### Notes
- Целевые пороги (3.0/3.9/10.0/13.9 ммоль/л) конфигурируются в каждом
  виджете отдельно — можно сменить под рекомендации эндокринолога.
- По умолчанию виджеты берут данные из `sensor.blood_sugar` и сопутствующих
  `sensor.glucose_*` — стандартный набор для Nightscout / Juggluco / Sibionics 2
  в HA. Имена сенсоров переопределяются в настройках виджета.

## [0.1.0-alpha.53] — 2026-05-15

### Changed
- **`CameraWidget` теперь показывает live-стрим через HLS.** Раньше виджет дёргал `entity_picture` (snapshot) раз в 5-10 секунд — «дёрганая» картинка с заметным запаздыванием. Теперь:
  - При mount запрашивается HLS-плейлист через WS-команду `camera/stream` (HA Stream Integration сама перекодирует RTSP/ONVIF в HLS).
  - На Safari (iOS/macOS) — нативный HLS, без дополнительных библиотек.
  - На Chrome/Firefox/Edge — через `hls.js` с `lowLatencyMode`, динамический импорт (~50КБ gzip только когда есть камера на странице).
  - Tier `'tiny'` остаётся на snapshot — держать stream ради превью ~80×64px бессмысленная нагрузка на камеру.
  - Фолбэк на snapshot если у камеры нет stream-source (дешёвые ESP/IP-камеры без RTSP) или если HLS падает.
  - Под HA Ingress URL стрима проходит через тот же proxy-роут `/api/glance/ha-rest/hls/...`, что и REST к HA — Supervisor-токен остаётся на сервере, не утекает в браузер.
- Заимствовано идеологически из reference-проекта `advanced-camera-card` (Dermot Duffy), но без зависимости от HA-frontend компонент `ha-hls-player` — у нас отдельное Next.js приложение, не Lovelace card.

### Dependencies
- Добавлено: `hls.js ^1.6.16`.

## [0.1.0-alpha.52] — 2026-05-14

### Fixed
- **На десктопе виджеты «прилипали» к левому краю.** Раскладка хранит один набор координат `w/h`. Раскладка, собранная в 9-колоночной сетке (как на телефоне или импортированная с другого устройства), на десктопе попадала в 24-колоночный грид и занимала левые ~37% ширины, оставляя справа огромную пустоту. Введён `MAX_GRID_WIDTH = 760`: грид-контейнер центрируется (`mx-auto`) и не растягивается шире 760px, а число колонок считается от `min(innerWidth, 760)` — на любом экране это 9 колонок. На десктопе дашборд выглядит как центрированная колонка, идентичная мобильной раскладке.

## [0.1.0-alpha.51] — 2026-05-14

### Fixed
- **Сущности с `disabled_by` / `hidden_by` не находились в пикерах настроек.** Пример: `sensor.blood_sugar` (интеграция nightscout) имеет `disabled_by='config_entry'` в entity registry, но реально активен и есть в `states` (отдаёт значение). Пикеры (`EntityPicker`, `MultiEntityPicker`, `MultiEntityCombinedPicker`) дополнительно резали такие сущности по registry-флагам — и рабочий сенсор был не виден. Теперь фильтр только по домену: если сущность есть в `states`, она активна и показывается. registry-флаги — это про витрину дашбордов HA, а Glance отдельная панель.

### Changed
- **`MultiEntityPicker` переписан под удаление крестиком.** Раньше это был свёрнутый список с галочками: чтобы убрать одну выбранную сущность, нужно было открыть весь каталог и найти её среди сотен. Теперь выбранные показаны отдельными строками с крестиком справа (как в `MultiEntityCombinedPicker`), добавление — через «+ Добавить» с поиском.

## [0.1.0-alpha.49] — 2026-05-14

### Fixed
- **`LightColorWidget` показывал голую иконку на минимальном размере.** tier `'tiny'` (только иконка-toggle, без названия) активировался по порогу `size.w < 90 && size.h < 90`. ## [0.1.0-alpha.48] — 2026-05-13

### Fixed
- **PWA cold-start больше не выкидывает в onboarding.** Connection хранилось только на сервере (`/api/glance/connection`). Когда PWA запускалась после выгрузки из памяти, сеть ещё не успевала подняться к моменту первого fetch — он падал в catch, `loadConnection()` возвращал `null`, `hasCredentials=false` → пользователь видел форму «введи URL+token», хотя реально connection давно настроено. Добавлено локальное зеркало (`localStorage`, ключ `hg.connection.v1`): пишется при `saveConnection`, читается как fallback в `loadConnection` если сетевой запрос упал. Источник правды остаётся серверный — при удачном fetch локальный кэш перезаписывается актуальным значением.

## [0.1.0-alpha.45] — 2026-05-13
